# Non-semver component version fix — design

## Problem

`output-dependencies.xlsx`, generated by `sbom_to_excel.py` from `sbom_new.json`,
has 10 rows (of 297) whose "Component Version" is not a clean X.Y.Z semver
string. Root-cause analysis found four distinct patterns:

1. **Maven 2-segment versions** (e.g. `1.8`, `1.84`, `2.21`, `3.2`) — legitimate
   Maven versions; Maven does not require 3-segment semver. **Not a defect.**
2. **Binary/URL downloads with no package-manager version** (BellSoft JRE zip,
   MongoDB Windows zip) — SPDX shows an MD5-like checksum or `NOASSERTION`
   instead of a real version. The real version (`17.0.19+11`, `8.0.17`) is
   embedded in the download URL/filename but was never extracted.
3. **Git tag as version** (`postgres` → `REL_18_3`) — valid identifier for a
   git-sourced dependency, just not semver. **Not a defect.**
4. **Git commit SHA as version** (`tl4-ui-internal` →
   `09868c77055f4077a0405f5702597b8f8f0dd0e7`) — the internal Angular app's
   repo wasn't tagged/versioned at scan time; the scanner fell back to the
   commit SHA. No GitLab access is available from this environment to resolve
   the SHA to a real tag.

## Decisions (confirmed with user)

- Pattern 1 (Maven 2-segment): leave unchanged.
- Pattern 2 (binary/URL downloads): extract the real version from the
  download URL automatically.
- Pattern 3 (git tag): leave unchanged.
- Pattern 4 (commit SHA): no automatic resolution (no GitLab access). Add an
  optional `--version-overrides overrides.json` CLI flag so a human can
  supply the real version manually; falls back to the SPDX value (the SHA)
  if no override is supplied.

## Design

### 1. `extract_version_from_download_url(pkg) -> str | None`

Pure function in `sbom_to_excel.py`. Applies only to packages with **no
`externalRefs`** (no purl — i.e. a direct binary/URL download) and a
`downloadLocation` that is not `NOASSERTION`. Searches the URL for the regex
`\d+\.\d+\.\d+(?:\+\d+)?`, taking the **last** match (closest to the
filename, most likely the actual version). Returns `None` if no match, in
which case the original SPDX `versionInfo` is kept as-is.

Applied in the row-writing loop: if the extracted version is not `None`, it
replaces `pkg.get("versionInfo")` before writing column 3.

### 2. `--version-overrides overrides.json` CLI flag (optional)

- JSON file: `{"<package name or SPDXID>": "<real version>"}`.
- Loaded once at startup. If the file path is given but doesn't parse as
  JSON, or doesn't exist, the script exits with a clear error (no silent
  failure).
- Looked up by package `name` first, then by `SPDXID`, before writing the
  version column. If found, overrides both the raw SPDX version **and** any
  value produced by `extract_version_from_download_url` (an explicit human
  override always wins).
- Ship an example file `version-overrides.example.json` with a commented
  placeholder entry for `19518/helion/tl4-ui-internal` (empty by default —
  filling it in is a manual follow-up, not part of this change).

### 3. No changes

- Maven 2-segment versions and git-tag versions are left untouched — adding
  logic to "fix" them would misrepresent legitimate version identifiers.

## Testing

Manual verification after regenerating `output-dependencies.xlsx`:
- BellSoft JRE row shows `17.0.19+11` instead of a checksum/`NOASSERTION`.
- MongoDB Windows row(s) show `8.0.17` instead of a checksum/`NOASSERTION`.
- Apache Commons CSV / Bouncy Castle / Jackson-annotations / oshi-json /
  postgres rows are unchanged.
- `tl4-ui-internal` still shows the commit SHA when no override file is
  passed, and shows the override value when `--version-overrides` points to
  a file containing an entry for it.
- Passing a non-existent or invalid `--version-overrides` file produces a
  clear error and non-zero exit, not a silent fallback.
